# VERIFY — 验证与交接

**输入：**实际代码差异、已确认请求/验收、适用契约和现有测试、可用环境与已有实施依据。

**输出：**真实检查结果、适用代码修复或可复现问题，以及 `docs/backend-developer/<feature-id>/implementation-notes.md` 和必要证据；小改动可在回复保留适用说明。

## 1. 确认检查对象与标准

读取请求、实际差异、验收和权威契约，定位真实版本、环境、项目测试配置与命令。旧计划或报告可作为来源，未经复验的旧结论不作为当前证据。按 [工作方法](../sprite-backend-developer-services/references/workflow.md)的工程纪律与职责边界控制范围；仅评审或咨询不自动扩成实现、发布或其他角色工作。

将变化结果、重要旧行为及相关授权、数据、失败、并发、兼容风险对应到适当检查，复用已有测试；不为没有行为变化的简单修改制造镜像测试。

## 2. 核对完整行为与真实边界

按 [边界与授权](../sprite-backend-developer-services/references/boundaries-auth.md)检查正常调用，以及实际相关的换用户/资源标识、跨租户、缺失权限上下文与输入边界。不要 mock 掉授权后只断言调用次数。已确认资源、HTTP 状态、响应结构、分页与权威 OpenAPI 主源按适用约定同查，兼顾提供方与消费者。

按 [集成与恢复](../sprite-backend-developer-services/references/integrations.md)选择成功、明确失败、结果未知后的重试、重复交付和中断路径，检查最终状态及业务副作用次数。核对事务、并发、幂等、取消、超时和运行信号；需要更深查询或迁移验证时使用可选 `sprite-backend-developer-data` 数据专项。

## 3. 运行、定位与复验

执行项目已存在或已核实的相关检查，记录精确命令/操作、对象、版本和实际结果。涉及迁移时分别记录代码审查、环境演练、实际执行及恢复验证；前一种证据不能代替后一种。未运行或受阻项注明原因及受影响结论。

实现/修复任务发现范围内问题时回 [IMPLEMENT](../sprite-backend-developer-implement/SKILL.md)修复并复验；评审任务交付可复现问题及证据。实现与验收冲突保留来源，不通过改变预期、弱化断言或隐藏失败获得通过。范围、架构或风险接受需新决定时只暂停依赖部分，沿用已有授权。

## 4. 审查差异并交付真实结果

检查实际差异中的越界改动、生成噪声、秘密、兼容破坏及无谓复杂度，保护无关工作。明确实际行为、变更路径和原因、技术约束/选择、验收对应检查、精确结果、未验证项、限制及下一步。

按 [模板与交付](../sprite-backend-developer-services/references/delivery.md)读取完整实施说明模板再填写；已有说明局部更新即可，计划/任务有则链接并同步状态，没有就写无。完整功能或需交接时将文档、日志及附件实际写入业务仓库 `docs/backend-developer/`，源码和测试保持原目录，给真实文件链接、仓库、相对 Git 根路径及依据版本。维护旧产物与已有索引，不另造空台账；跨 Git 交接不能把未提交/推送说成远端可获取。

## 完成条件与下一步

- 变化与重要旧行为有相应实际检查，失败、未运行和受阻范围真实记录。
- 契约、授权、输入、数据不变量及相关失败/兼容路径的结论有证据。
- 实际差异已审查，代码、测试、说明和必要证据可追溯。
- 实现成功、测试通过与已经发布分别说明；最终发布不由验证结论自动授权。

在当前任务范围内交付验证或评审结果；已授权的相关修复需继续复验完成。后续发布、迁移执行或恢复只按当前明确授权和实际约束衔接。
