# IMPLEMENT — 实现完整服务调用链

**输入：**已确认请求或实施计划、适用契约、相关代码/测试及当前授权范围；不要求先创建独立计划文件。

**输出：**工程原生目录中的实际服务代码、适用契约/迁移/配置与测试，以及重要实现决定和待验证项。

## 1. 核对依据与编辑范围

读取当前请求、相关计划、代码与测试，确认来源和固定版本仍适用。仅有缺口时回 [PLAN](../sprite-backend-developer-plan/SKILL.md)补齐受影响依据。先读 [工作方法](../sprite-backend-developer-services/references/workflow.md)的职责范围、代码与工程纪律、职责与授权边界，沿用已有答案和授权。

在已授权开发范围内选择适用框架、库、工具与所需依赖，普通选择简述理由；不擅改范围、验收、架构、共享契约、兼容和安全规则。共享文件编辑前确认单一编辑者与顺序，保护用户和无关修改。数据库/数据变更、技术迁移和新建应用须在对应授权范围，不能把写迁移代码当成可执行生产迁移。

## 2. 实现入口、规则与可信边界

沿入口 → 领域规则 → 持久化/外部副作用完成最小完整结果，保留已有可用模块与接口风格。读 [边界与授权](../sprite-backend-developer-services/references/boundaries-auth.md)，核对输入结构、规模、未提供/空值/默认值及业务不变量；在可信位置验证主体能否操作具体资源，覆盖归属、租户和后台任务权限上下文。

使用领域命名、内聚模块、显式依赖和直接控制流，注释解释原因；仅为真实边界或当前重复概念增加抽象。诚实使用类型，区分业务拒绝与系统故障，在有上下文或恢复能力的位置处理错误；响应、日志、代码及测试不泄密，不吞错或伪装成功。

## 3. 处理数据与外部副作用

按任务核对事务、一致性、并发、幂等、取消、超时和相关运行信号。涉及集成或后台任务时读 [集成与恢复](../sprite-backend-developer-services/references/integrations.md)：结果未知先核对远端状态和幂等能力，重试有条件与上限；重复、乱序、中断及部分完成必须能观察和处理。日志、指标与跟踪复用现有设施。

接口和数据变化同步消费者、旧数据与部署期兼容；权威 OpenAPI YAML 发生行为变化时同改同查主源及受影响调用方/提供方。需要深化时读可选 `sprite-backend-developer-data` 数据专项，缺少它不阻碍充分依据下的本职实现。迁移按真实授权区分代码、演练和实际执行，保留恢复限制。

先测量再优化，避免明显重复 I/O、无界查询或缓存；新增依赖核对维护、安全、运行和包体成本。只在负载或故障证据支持时增加复杂隔离、熔断或扩容机制。

## 4. 更新测试与实施记录

行为变化新增或更新真实测试，覆盖变化结果、重要旧行为及相关权限、失败、数据一致性和兼容路径，关注可观察结果，不只断言调用次数。选择已存在或已核实的检查入口，不弱化断言、隐藏失败或凑测试数量。

更新已有计划/任务中的实际进展、实现选择与理由，记录验证所需环境、数据及尚未验证项。完整模板使用与业务文档保存按 [模板与交付](../sprite-backend-developer-services/references/delivery.md)；小改动可在回复保留适用内容。只移除已确认无用的代码，不借机扩展清理或迁移。

## 完成条件与下一阶段

- 目标调用链与相关授权、输入、数据和失败规则已实现。
- 契约、消费者、兼容及相关测试与实际变化一致。
- 实施决定、剩余缺口与验证条件可交接；实现完成未冒称测试通过或已经发布。

默认继续 [VERIFY](../sprite-backend-developer-verify/SKILL.md)运行检查、审查差异并交付。用户明确只要代码草稿或不执行时，在当前阶段交付并标明未运行项。
