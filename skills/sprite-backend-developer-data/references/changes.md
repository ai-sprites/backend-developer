# 变更与恢复

先核对当前授权、目标环境、数据范围、读写消费者与执行工具。明确“编写迁移代码”“在测试环境演练”“执行生产变更”分别是否属于本次任务；已有明确授权不重复索取，角色或实践本身不会增加权限。

涉及旧应用仍运行的变更时，考虑先增加兼容结构，再切换读写，必要时回填并验证，最后移除旧结构。只采用实际需要的步骤，不把所有小变更扩展成长期双写。双写要说明权威来源、失败补偿和结束条件。

批量回填关注规模、锁、负载、断点、重复执行和部分失败。先在合成或经授权的合适数据上验证映射、边界和约束；大批量任务需要可观察的进度与停止条件，不靠预估行数声称完成。

恢复方式取决于变化是否可逆。回退应用不会恢复已删除或覆盖的数据，反向迁移脚本也不保证信息能找回。核实可用备份、恢复范围与恢复后验证；没有做过恢复演练就明确标为未验证，不许诺无损回滚。

例如把自由文本转换为受限值，先统计不能映射的内容，再确定保留或人工处理规则；未知值不静默归为某个默认类别。映射规则待定只限制相关数据的转换，其他可独立准备继续。

记录实际版本、命令、数量或差异与检查结果，确认约束、代表性业务路径和旧消费者兼容。只在交接或追溯需要时保存这些记录，日志及测试夹具不包含秘密或私人生产资料。
