# 一致性与查询

先写出数据不变量，例如同一资源不能出现两次有效占用，再定位哪些操作可能并发改变它。应用里的先查后写可能有竞态；根据当前存储能力选择约束、事务、锁或版本检查，核对实际隔离级别与重试语义。

事务保持必要而短的工作范围，避免在持锁期间等待慢外部调用；跨数据库或外部服务不能被一个本地事务自动保护。失败要么有明确回滚，要么能观察到部分完成并采取恢复措施，不宣称不存在的原子性。

查询只取所需字段和范围，关注重复查询、无界扫描、排序及分页。先用代表性的合成数据和实际执行计划定位成本，再考虑索引或重构；索引也会增加写入与维护成本。测量条件与生产差异要说明，不能因小样本快就保证规模性能。

缓存明确权威数据来源、键的租户与权限边界、失效和过期策略。缓存未命中与源数据不存在不同；缓存更新失败不能默默破坏已承诺的一致性。搜索或对象存储有不同的一致性、清理和访问规则，按本次路径核对。

需要隐私、保留或审计处理时使用已确定规则，区分删除、脱敏与保留证据。没有合法或业务依据时记录待定内容，不凭经验编造保留期限。

若项目已使用 PostgreSQL，可查 [事务隔离官方文档](https://www.postgresql.org/docs/current/transaction-iso.html)；其他存储查其对应版本，不能把某个数据库的隔离行为泛化到全部系统。
