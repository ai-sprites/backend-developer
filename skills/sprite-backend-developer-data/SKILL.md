# 数据工作

按项目约定和实际数据任务选择所需工具，不预设数据库、ORM 或迁移平台。本实践可以单独使用，不依赖后端阶段组合或其他角色。

**输入：**数据问题或已授权变更、相关需求/验收、适用契约、代码与测试、真实环境和版本。

**输出：**当前数据问题的代码、方案或执行结果及验证记录；实际实现或变更保存到 `docs/backend-developer/`，单次简单只读分析可在回复记录适用内容。

## 1. 明确问题、依据与实际范围

读取请求、已确认设计与技术约束、代码、契约和测试，记录真实来源与版本。先读 [工作方法与交付](references/workflow.md)，沿用已有答案、授权和适用工具约定；重要决定缺失只暂停依赖部分，不代写其他角色的决定。

明确本次是查询分析、实现修复、迁移代码、环境演练还是实际数据执行。普通工具与依赖选择属于已授权本职范围，技术迁移、数据变更、发布和恢复仍须符合对应范围和约束；已有授权不重复索取。

## 2. 核对数据所有者与不变量

查询、事务、并发和缓存读 [一致性与查询](references/consistency-query.md)。写清不变量与并发修改入口，按实际存储能力核对约束、事务/隔离、锁或版本检查；跨服务不假设本地事务能提供原子性。

查询优化先用代表性数据和执行计划定位成本，说明与生产的差异。缓存核对权威来源、租户/权限边界、失效与过期；隐私、保留和审计采用已确定规则，不编造期限。

## 3. 处理本次真正需要的数据变化

涉及结构、数据或存储切换读 [变更与恢复](references/changes.md)。确认读写消费者、兼容窗口、操作顺序和旧数据处理，按需要使用兼容结构、回填或切换，不把小变更扩成长期双写。

核对规模、锁、负载、断点、重复执行和部分失败；未知映射不静默归默认值。区分应用回退与数据恢复，检查可用备份、恢复范围及恢复后验证，未演练明确标未验证。

## 4. 实施、验证与审查

按当前授权实现或修复，保护秘密和用户工作，保持领域命名、明确输入输出与失败语义、直接控制流及必要边界。行为变化覆盖新结果与重要旧行为，执行已核实的项目检查；不凑镜像测试，不弱化断言或编造结果。

记录实际命令、数量/差异及检查结果，核对约束、代表性业务路径和旧消费者兼容。区分代码审查、演练、实际执行与恢复验证，审查真实差异中的越界、噪声、秘密、兼容破坏及无谓复杂度。

## 5. 交付当前完成状态

按 [完整交付与留存规则](references/workflow.md)记录需求/授权与技术依据、环境/版本、数据所有者和不变量、消费者、变化原因、兼容顺序、精确检查、未验证项及原因、风险、恢复办法和后续验证。没有数据变更的查询任务不制造迁移步骤。

记录和必要证据实际写入业务仓库 `docs/backend-developer/`，例如 `<feature-id>/data.md`；源码、测试、迁移和配置保持原目录。保护旧产物、自定义及已有索引，给真实链接和版本，未提交/推送不冒称远端可取；跨 Git 仅在确有需要时按工作方法复用或补齐 bridge。

## 完成条件与下一步

- 问题、范围、来源、数据所有者和不变量明确。
- 实际相关的一致性、查询、兼容和恢复路径有依据与验证。
- 完成阶段、未验证项和剩余影响真实，代码/方案/执行结果与记录可追溯。

实现或修复任务继续完成范围内相关检查；只读分析交付结论即可。需要后续真实数据执行、发布或恢复时按当前明确授权衔接，不能把方案完成当作执行授权。
