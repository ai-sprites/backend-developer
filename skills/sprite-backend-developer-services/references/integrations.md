# 集成与恢复

先区分请求未发送、明确拒绝、已处理和处理结果未知。超时通常只能说明未及时收到结果，不能证明远端没有执行；涉及副作用时先核对远端幂等或查询结果能力，再决定重试。

设置符合当前调用链的超时预算和取消传播。重试限定可重试条件、次数或总时长，并考虑退避与并发上限；多层各自重试可能放大请求。回退应有真实业务含义和可见信号，不能吞掉失败把旧数据当新结果。

幂等要明确操作身份、调用者范围、相同键不同参数的行为和结果保存条件。先检查已有机制，不直接增加独立存储或服务。重复与并发同时到来时，确保检查和副作用不会因竞态各执行一次。

后台任务或事件消费者需要处理重复、乱序、中断和恢复，确认失败记录、重放与终止条件。若写数据和发消息之间有一致性需求，先说明当前事务边界和失败窗口，再选择已有事务消息、补偿或其他适用办法，不把某种模式设为必需。

观察信号应能回答什么失败、影响了哪些请求或任务、是否恢复。日志、指标和跟踪选用现有基础设施，关联信息要去除秘密；只有负载或故障证据支持时才加入复杂隔离、熔断或扩容机制。

验证典型成功、明确失败、响应丢失后的重试、进程中断或重复交付中实际相关的路径，检查业务副作用次数与最终状态，而不只检查函数被调用。
