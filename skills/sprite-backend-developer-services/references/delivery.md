# 后端模板与交付

## 按任务选择完整模板

三份文件各有用途，普通小变更不强制全部创建；开发范围填写 `backend` 或当前明确扩展的实际范围。

| 模板 | 何时使用 | 填成什么 |
| --- | --- | --- |
| [实施计划](../assets/templates/implementation-plan.md) | 复杂、多步骤、有风险或跨重要区域/仓库，需要持久实施依据时，在改动前读取 | 目标、保留行为、实施顺序、仓库变更、验收、契约协调及风险决定 |
| [实施任务](../assets/templates/implementation-tasks.md) | 清单能改善排序、并行分工或验收覆盖时读取 | 可执行任务、依赖、负责人分工相关信息与实际证据/阻碍 |
| [实施说明](../assets/templates/implementation-notes.md) | 功能完成或受阻后需要交接时读取；简单小改动可在回复中覆盖适用内容 | 真实状态、变更及原因、采用决定、精确检查结果、限制、覆盖和后续验证 |

更新实际计划/任务状态，将命令、结果和未验证项写入实施说明；交付代码和真实业务文档链接，不只给模板链接。完整交付内容与资料桥接规则见 [工作方法](workflow.md#交付) 和 [产物留存与交接](workflow.md#产物留存与交接)。

## 填写、保存与维护

读取选中的完整模板后再填充；保留原章节和字段，填入真实业务信息。已有文档结构可继续沿用，但须覆盖模板中的适用内容；无关字段写无或不适用，不编造数据、负责人、批准或执行结果。Markdown 占位链接采用 `(<...>)`；业务产物中的链接必须替换为真实路径，不保留模板路径作为交付地址。

已有产物先读取并局部更新，保留仍有效的结论；说明替代了哪些旧依据，未重新验证的旧结果不能冒充当前证据。按工作方法将业务文档及附件实际保存到业务仓库 `docs/backend-developer/`（可在角色目录下按功能分组），给出真实链接、仓库、相对 Git 根路径和依据版本；不能保存时如实说明，不能声称已交付。已有本职产物散落在其他位置时，先读取并保留有效内容，再迁入 `docs/backend-developer/`，同步文内链接、其他引用及已有索引；遇到同名文件先比较并合并，避免覆盖用户内容。源码、测试、迁移、配置及构建输出保持工程原生目录；角色和 Skill 安装资源保持客户端目录。维护项目已有索引，不为本任务强建全局登记；文件未提交或未推送就不能声称其他 Git 仓库已可读取。

需要的工作模板或引用缺失时，从 [本角色仓库](https://github.com/ai-sprites/backend-developer) 的同一明确版本补齐完整总流程与所需同级阶段（包括各自 `SKILL.md`、共享 `references/` 与 `assets/`，依赖范围见 [接入手册](https://github.com/ai-sprites/backend-developer/blob/main/docs/installation.md)），保留用户自定义；不要编造简版冒充原模板。无法补齐时说明缺失与限制，继续有充分依据的独立部分。
