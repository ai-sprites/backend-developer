# 边界与授权

从一个业务动作找到入口、规则、持久化和外部副作用。模块、函数和接口应表达当前责任，依赖方向能看出谁调用谁；仅在当前所有权、部署、容量或隔离确有需要时拆服务。无需在每层重复相同数据模型和校验。

在不可信输入进入时检查结构与约束，在规则真正生效处维护业务不变量。区分未提供、空值和默认值，限制会影响资源占用的输入规模。不要用弱化类型或泛化错误掩盖数据无法满足契约。

认证识别主体，授权核对该主体能否操作这个资源。检查请求目标、资源归属、租户边界、功能权限和必要的属性限制；不能只验证用户已登录。后台任务和内部调用也要知道使用谁的权限与哪份资源范围。

错误在能添加上下文或恢复的位置处理。预期的业务拒绝与系统故障分开，调用者可识别且不会看到内部秘密；保留可关联的诊断信息，不能静默返回空结果伪装成功。

验证正常调用外，还检查换一个用户或资源标识、跨租户、缺失授权上下文及输入边界。用真实服务边界与测试工具，避免只 mock 掉授权后断言调用次数。

延伸阅读：[OWASP 授权检查说明](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)。采用与当前服务相关的建议，不因实践安装而改变项目的角色或权限模型。
