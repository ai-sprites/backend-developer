# 后端开发工作流

沿真实业务调用链完成当前已授权的实现、修复或评审，明确职责、数据与信任边界，复用当前技术。角色不是前置条件；本职流程由总入口、三个阶段及共享参考组成。

## 工作顺序

```text
请求 / 验收 / 代码 / 真实契约
        │
PLAN    sprite-backend-developer-plan       → 实施依据与验证安排
        │
BUILD   sprite-backend-developer-implement  → 服务代码、契约与测试
        │
VERIFY  sprite-backend-developer-verify     → 真实检查与实现说明
        └─ 实现问题 → BUILD → VERIFY

数据一致性、查询或迁移需要深化时 → sprite-backend-developer-data
```

| 阶段 | 输入 | 完成条件 |
| --- | --- | --- |
| [Plan](../sprite-backend-developer-plan/SKILL.md) | 已确认请求、代码、技术约束和契约 | 范围、保留行为、改动顺序、共享分工及检查清楚 |
| [Implement](../sprite-backend-developer-implement/SKILL.md) | 已明确的实施依据或现成计划 | 最小完整调用链落地，适用契约和测试同步 |
| [Verify](../sprite-backend-developer-verify/SKILL.md) | 实际差异、验收与可用环境 | 运行相关检查、审查差异、交付真实结果和未验证项 |

完整实现任务按顺序推进；已有充分依据直接 Implement，已有改动要验证或评审直接 Verify。简单改动可在当前上下文衔接阶段，不强建计划和任务表。仅咨询已有成果时盘点相关结果与缺口，不启动新增实现。

## 执行规则

1. 以已确认范围、验收、架构和权威契约为准。普通本职框架、库、工具与依赖选择自行完成并简述理由；需人的重要决定沿用已有答案和授权，只暂停依赖部分。
2. 沿真实业务调用链实现最小完整结果；在可信边界执行校验和授权，核对数据不变量、事务、并发、幂等、兼容和相关失败。
3. 共享契约、公共库、根配置、CI 和公共测试在编辑前明确单一编辑者与交接顺序，独立文件可并行。
4. 新建应用、技术迁移、数据库或数据变更、合并、发布和恢复必须属于当前授权范围；区分迁移代码、演练与实际执行，不重复索取已有授权。
5. 行为变化覆盖新结果与重要旧行为；不弱化断言、隐藏失败、泄露秘密或编造结果。实现成功、测试通过与已经发布分别以证据判断。

专业方法与完整边界保留在 [工作方法](references/workflow.md)。阶段按任务读取相关章节，不要求其他角色、完整 PRD 或固定 SDLC。

## 产物

```text
docs/backend-developer/<feature-id>/
├── implementation-plan.md    按复杂度需要
├── implementation-tasks.md   仅在排序、分工或覆盖有价值时
├── implementation-notes.md   实际变化、决定、检查和后续验证
└── evidence/                 必要证据与附件
```

源码、测试、迁移、配置及构建输出保持工程原生目录。完整功能或需要交接时保存实施说明；小改动可在回复覆盖适用内容。模板选择、旧产物迁移、真实链接和缺失资源处理见 [模板与交付](references/delivery.md)。

## 全流程完成检查

- [ ] 范围、真实来源与版本、验收、契约和重要保留行为明确。
- [ ] 调用链实现完整；相关授权、数据、失败、兼容和运行信号有实现与验证。
- [ ] 行为变化有适当测试，实际差异在授权范围内。
- [ ] 精确检查、结果、限制和后续验证已交付，旧结论未冒充当前证据。
- [ ] 必要业务文档与附件已实际保存，链接、已有索引与任务状态同步。
