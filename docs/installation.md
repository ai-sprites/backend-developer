# 接入 backend-developer

完整接入包含角色说明、总流程和三个同级阶段 Skill；用户可粘贴 [README 的接入说明](../README.md)，由 AI 识别客户端并完成安装。

## 1. 固定版本，读取完整资源

根据当前会话和项目情况判断客户端，沿用它支持的接入方式；不确定且影响接入时再查证或询问用户。从同一明确版本读取 README 的完整资源清单、[角色定义](../templates/agent.md)，以及下面四个完整目录：

- [sprite-backend-developer-services](../skills/sprite-backend-developer-services/SKILL.md)
- [sprite-backend-developer-plan](../skills/sprite-backend-developer-plan/SKILL.md)
- [sprite-backend-developer-implement](../skills/sprite-backend-developer-implement/SKILL.md)
- [sprite-backend-developer-verify](../skills/sprite-backend-developer-verify/SKILL.md)

网页来源先固定到完整 Git 提交再取同批资源，本地未提交内容如实标注；不能读取原文就说明缺项，不编造替代版本。历史 `v0.2.0` 可明确采用，内容及能力以该标签为准。

[`sprite-backend-developer-data`](../skills/sprite-backend-developer-data/SKILL.md) 是可选独立专项，按明确请求或实际任务需要完整安装其自身目录；默认服务阶段组合不依赖它。也可以直接要求追加数据专项并保留其他内容。

## 2. 保持四个同级 Skill 完整落盘

默认将四个目录原样放入同一个客户端 Skill 根目录，保留每个 `SKILL.md` 的名称、完整正文和内部相对结构，以及 `sprite-backend-developer-services/references/`、`assets/` 的全部工作方法与模板。每个阶段可单独调用；安装时依然需要共享参考及其链接到的同级阶段，不能把“单独执行”理解为只复制一份入口。

只适配必要的目标客户端目录、元数据格式和角色入口引用，不摘要改写专业内容，不把阶段重新合成一个大 Skill。角色正文放到客户端支持的位置；保护项目已有规则和自定义。角色负责职责与路由，实际工作读对应阶段。

用户明确只要角色时说明尚未带入执行能力；明确只要部分能力时，沿所有本地引用递归补齐当前已授权安装所必需的同级依赖，直到入口、阶段跳转、工作方法和模板全部可达，并说明实际安装范围。当前四个流程目录彼此衔接，通常仍需完整组合。不要顺便安装未选专项或其他角色。

接入本身不执行业务任务、不填写模板、不建立安装登记，也不配置账号、CI、定时任务或外部通知。相同内容直接复用，已有同名内容先比较来源与正文，保留自定义；实质冲突只处理相关部分。

## 3. 升级旧单体版

旧版 `sprite-backend-developer-services` 名称继续作为总流程入口，不改名、不使已有调用失效。

1. 对照当前来源版本与旧文件，先保留原角色、Skill、工作方法、模板中的用户自定义，识别其属于哪个阶段或共享参考。
2. 补齐总流程、三个阶段及完整共享目录，把旧自定义按职责合入对应阶段/参考；无法自动合并的部分保留原文并说明具体冲突。
3. 更新直接指向旧大入口内部步骤的调用或项目说明，指向实际阶段；通用调用仍可用原总流程名称。
4. 核验完整正文、模板与所有本地引用后完成替换。需要保留旧副本时放到 Skill 自动发现目录之外，避免新旧重复生效；不能删除未迁移自定义。

不删除业务文档、证据、工程配置、代码或未选 Skill。安装资源更新与业务产物迁移分开，后者按下述交付规则保留有效内容。

## 资料和产物放哪里

资料来源仓库（host repo）与产物业务仓库可以不同，已明确的仓库直接沿用；尚未明确的仓库合并用白话问一次，允许稍后确定并先完成接入，实际使用时再补必需版本和文件。上游资料按真实路径读取。本角色生成的业务文档及附件统一保存在业务仓库 `docs/backend-developer/`，可在角色目录下按功能分组，不另行选择散落位置。已有本职产物散落在其他位置时，先读取并保留有效内容，再迁入 `docs/backend-developer/`，同步文内链接、其他引用及已有索引；遇到同名文件先比较并合并，避免覆盖用户内容。源码、测试、迁移、配置及构建输出保持工程原生目录，角色和 Skill 安装资源保持客户端目录。

本地资料直接使用。确需跨 Git 读取、固定版本或导出时，按 [bridge 接入手册](https://github.com/ai-sprites/artifact-bridge/blob/main/docs/installation.md)复用或补齐完整 Skill 并告知用户，无需另发安装指令；用户已拒绝或条件不足时说明限制。角色可以独立使用，业务留存见 [产物交接说明](artifact-handoff.md)。

## 已有内容与后续维护

沿用已有角色和 Skill 安装资源位置；相同内容直接复用，用户自定义保留，实质冲突只询问相关部分。更新时完整采用同一版本，补齐总流程、阶段与共享依赖，核对所有本地引用；不因追加或更新删除未选资源。移除只处理用户指定范围，保护自定义及仍被引用的文件。

## 完成后告诉用户

核对四个 `SKILL.md`、完整共享参考与模板、角色文件及所有相对引用；可选专项核对自身完整目录。简明说明来源版本、实际安装范围、保存位置与调用方式。按当前环境验证加载情况，区分“已保存”“已加载”和“已执行”。

需要用户亲自完成的步骤，按现场情况列成简短清单；没有就不加。只有聊天权限时可先在本会话使用，明确未写入项目及尚未完成的部分。
